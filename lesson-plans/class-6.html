Mini-Lecture — Mapping Rules 1–4
  • Rule 1 — Strong Entity: Entity → Table. Entity name = table name. Key attribute = primary key. Simple attributes = columns.
  • Rule 2 — Weak Entity: Create table. Include owner's PK as foreign key. Composite PK = partial key + owner's PK.
  • Rule 3 — Binary 1:1 Relationship: Choose one entity's table, add the other's PK as foreign key (prefer total participation side).
  • Rule 4 — Binary 1:N Relationship: Add the 1-side entity's PK as a foreign key in the N-side entity's table.
  • Worked example for each rule using Employee-Department scenario
11:15 – 11:40
25 min
Mini-Lecture — Mapping Rules 5–8
  • Rule 5 — Binary M:N Relationship: Create a new relationship table. Include PKs of both entities as foreign keys. Composite PK = both FKs.
  • Rule 6 — Multivalued Attribute: New table with: entity's PK (FK) + attribute value. Composite PK = both columns.
  • Rule 7 — N-ary (Ternary) Relationship: New table. Include PKs of all participating entities as foreign keys.
  • Rule 8 — Composite Attribute: Expand into individual simple attribute columns in the entity's table. Do NOT create a separate table.
  • Worked example: Map the Hospital ER diagram from Class 5 using all 8 rules

🧠 8 Mapping Rules Summary
  • Rule 1: Strong Entity → Table (PK = key attribute)
  • Rule 2: Weak Entity → Table (composite PK)
  • Rule 3: Binary 1:1 → FK in one table
  • Rule 4: Binary 1:N → FK in N-side table
  • Rule 5: Binary M:N → New relationship table
  • Rule 6: Multivalued attr → New table
  • Rule 7: N-ary relationship → New table
  • Rule 8: Composite attr → Expand columns

Instructor Notes
📝 Pedagogical Notes for the Instructor
  • Rule 3 vs Rule 4: Students frequently confuse 1:1 and 1:N mapping. Emphasise: in 1:1 you CHOOSE which table gets the FK (prefer total participation side). In 1:N it is always the N-side.
  • Rule 5: The most important rule for relational design. Ensure students understand that M:N relationships ALWAYS require a new table — never a direct foreign key between the two entity tables.
  • Own ER diagram: Using students' own Class 4 work for mapping creates metacognitive ownership — they see errors in their ER design as they try to map it. This is powerful learning.
  • Peer assessment quality: Model the feedback format on the board: "Rule 4 was correctly applied — the employee_id FK is in the works_on table (N-side)."
  • ER Knowledge Check: Remind students the badge system rewards first-attempt excellence — encourage them to study before attempting rather than trial-and-error clicking.
