Mini-Lecture — Functional Dependencies
  • Definition: X → Y (X functionally determines Y — knowing X always tells us Y)
  • Full functional dependency: Y depends on the ENTIRE composite key, not just part of it
  • Partial dependency: Y depends on only PART of a composite primary key
  • Transitive dependency: X → Y → Z (non-key determines another non-key)
  • How to identify: "Does knowing X always, necessarily tell us Y?"
  • YooBees: Normalization deck — slides 1–5 (Functional Dependencies)

15 min
Mini-Lecture — First Normal Form (1NF)
  • 1NF requirements: (1) Each column contains atomic values, (2) No repeating groups, (3) Each row is unique (has a primary key)
  • Common violations: storing multiple phone numbers in one cell, comma-separated values, arrays
  • How to achieve: decompose multi-valued cells into separate rows or separate tables
  • Activity: Students fix a given 0NF table to 1NF in pairs

SESSION 2 — 2NF, 3NF, BCNF & Normalization Practice
12:00 – 12:25

Mini-Lecture — 2NF, 3NF & BCNF
  • 2NF: Must be in 1NF + no partial functional dependencies. Only applies to tables with composite PKs. Remove attributes that depend on only PART of the PK into a new table.
  • 3NF: Must be in 2NF + no transitive dependencies. All non-key attributes must depend ONLY on the primary key. Remove: CourseName → InstructorID → InstructorEmail into Instructor table.
  • BCNF: Every determinant must be a candidate key. Stronger than 3NF — handles edge cases where 3NF tables still have anomalies due to multiple overlapping candidate keys.
  • SQL execution order connection: how normalisation maps to efficient query design
  • YooBees: Normalization deck — slides 10–18 (2NF, 3NF, BCNF with worked examples)

Instructor Notes
📝 Pedagogical Notes for the Instructor
  • Discovery first: Do NOT explain anomalies before the discovery activity. Let students encounter them first — the "aha moment" creates durable learning (constructivist pedagogy).
  • 2NF only applies with composite PKs: Remind students repeatedly. A table with a single-column PK automatically satisfies 2NF if it satisfies 1NF.
  • 3NF test: Teach the simple test: "For every non-trivial FD X → Y, either X is a superkey OR Y is a prime attribute." Use this with students when they are uncertain.
  • BCNF depth: BCNF is introduced conceptually — students are not expected to perform BCNF decomposition in assessments, only to recognise violations.
  • Socratic seminar: Seed the discussion with a performance scenario: "An e-commerce site queries 10 million orders per second — would you normalise the orders table?" This makes denormalisation concrete.
