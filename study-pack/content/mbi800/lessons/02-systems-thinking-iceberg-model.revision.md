## Systems vs collections

- **Collection** = items with no interaction; removing one changes nothing else.
- **System** = interacting parts; removing/changing one changes how the others behave.
- Test: bowl of fruit (collection) vs football team (system).

## Systems thinking

Replaces two habits:

1. Linear cause-and-effect → **interrelationships** among parts.
2. Discrete snapshots → **processes of change over time**.

::: tip
The blindfolded-elephant parable: each investigator is correct about their part, wrong about the whole. No single vantage point in an organisation sees the full system.
:::

## Feedback loop example

Inadequate selling effort → out-of-date sales procedures (processing) → poor sales performance (output) → incorrect sales information fed back → poor sales management (control) → reinforces inadequate selling effort.

**Lesson:** blaming the output (sales team) ignores the loop that produced it.

## The Iceberg Model (Senge, 1996)

| Layer | Question | Visibility / Leverage |
|---|---|---|
| Events | What's happening? | Most visible, least leverage |
| Patterns of Behaviour | What's been happening? Trends? | ↓ |
| Structures | Policies, workflows, resource allocation causing the pattern | ↓ |
| Mental Models | Values, beliefs, assumptions underneath the structures | Least visible, most leverage |

**Learning** and **Leverage** both increase going *down* the iceberg.

::: warning
Most organisations spend nearly all improvement effort at the Events layer — it's the only one visible without deliberate digging.
:::

## Applying the model (exam pattern)

1. State the **event** precisely.
2. Find the recurring **pattern**.
3. Identify the **structures** (policy/workflow/resourcing) producing the pattern.
4. Name the **mental model** (belief/assumption) that lets the structures persist.
5. Durable fixes target Structures/Mental Models, not just the Event.

**Worked case:** CrowdStrike/Windows outage 2024 — event (crash) → pattern (unreviewed emergency updates correlate with outages) → structure (kernel-level deploy, no staged rollout) → mental model (vendor updates assumed low-risk).
