## Strategic planning cascade

Purpose + Vision + Values → **Mission Statement** → Goals → Objectives → Business Operations (fed by IT + other resources) → Business Results → Stakeholders.

A systems request with no path back up this chain has no business case yet.

SWOT → critical success factors → critical business issues → case for action.

## Why systems requests happen

Improved services · support for new products/services · better performance · stronger controls · more information.

## Internal vs external factors

| Internal | External |
|---|---|
| Strategic plan | Technology & vendors |
| Top managers | Suppliers (JIT) |
| User requests | Customers (CRM) |
| IT department | Competitors |
| Existing systems | Economy · Government |

## Evaluating requests

Systems review committee (large firms) or one manager (small firms) + a **standard request form** → consistent comparison + priority.

## Four feasibility tests

| Test | Question |
|---|---|
| Operational | Will it actually be used effectively? |
| Technical | Can current tech/expertise support it? |
| Economic | Does benefit justify cost? |
| Schedule | Can it be done in a useful time frame? |

::: warning
Passing 3 of 4 isn't enough — technically/economically sound but operationally rejected still fails.
:::

## Setting priorities

Reduce costs? Increase revenue? More/better info (measurable)? Serve customers/org better? Reasonable time frame? Resources available?

Prefer **tangible** ($ value) over intangible claims.

## The SDLC (5 phases)

1. Problem Definition — requirements, constraints, approval
2. Feasibility Study (see above)
3. System Analysis — document existing, gather new requirements
4. System Design — conceptual → detailed specs
5. Development & Implementation — build, **conversion**, **training**, **changeover**

Systems planning = **phase 1 of the SDLC**.
