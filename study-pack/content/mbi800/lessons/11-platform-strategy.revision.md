## Pipes vs products vs platforms

- **Pipeline** — owns whole value chain, one-way flow
- **Product** — one offering, sold directly
- **Platform** — connects 2+ groups; owns rules/infra, not necessarily the product

Platforms **orchestrate** value; they don't have to **own** it.

## Network effects (4 types)

| Type | Example |
|---|---|
| Cross-side positive | More drivers → shorter waits (ride-hailing) |
| Same-side positive | More friends → more useful (messaging) |
| Same-side negative | Too many drivers → lower earnings each (congestion) |
| Data network effect | Every interaction improves recs for everyone (Netflix) |

::: warning
Not all growth is good — manage negative effects too.
:::

## Chicken-and-egg tactics

Subsidise one side (Uber → drivers) · single-player mode (early Airbnb browsing) · seed own supply (Amazon/Zappos) · piggyback a network (PayPal on eBay) · target a micro-market (Facebook at one campus).

## Multi-homing

Single-homing = one platform. Multi-homing = several at once (hotel on Booking.com + Expedia).
Low switching cost → several platforms survive. High switching cost → market **tips** to one winner.

## 3 platform types (Cusumano, Gawer & Yoffie)

| | Transaction | Innovation |
|---|---|---|
| Does | Lets people transact | Gives 3rd parties a tech base |
| Revenue | Commission/fees/subscription | Licensing/rev-share/cloud sales |
| Governance | Trust, ratings, fraud | Developer relations, API stability |
| Examples | eBay, Airbnb, Uber, Stripe | Windows, Android, AWS |

**Hybrid** = both (Apple iOS/App Store; Amazon Marketplace/AWS).

## 4 decisions to build a platform

1. Choose your sides
2. Solve chicken-and-egg
3. Design the business model (who pays, how much)
4. Set governance rules (how open, who shares value)

**Boundary resources** (APIs/SDKs/review) balance **resourcing** (enable) vs **securing** (control).

## Case: Amazon flywheel

Marketplace (transaction) + AWS (innovation, started internal → sold externally, even to rivals). Flywheel: lower prices + selection → traffic → sellers → lower costs → repeat.

## Case: GE Predix ($4B, 2014→2022)

Failed on: **scope overreach** (aviation+health+oil&gas at once) · **built own cloud** (vs AWS/Azure) · **not developer-friendly**.

## Does it pay off?

43 public platform cos: same revenue, half staff, 2x profit, 2x growth. Unicorn valuation premium: NA +129%, Europe +68%, APAC +39%.

## Where it goes wrong

Mispricing · cold-start failure · scope overreach · trust collapse · dependence · regulation/antitrust.
